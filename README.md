# RAMASH — متجر أزياء باستخدام Laravel

متجر محلي مبني بتاريخ **6 نوفمبر 2026**، مستلهم من تنظيم وتجربة لومار، بهوية RAMASH مستقلة. المشروع مثبت داخل:

`/Users/yunessaif/Developer/ramash/store`

## التشغيل الآن

PHP وComposer والحزم وقاعدة SQLite مثبتة بالفعل في هذا المجلد. افتح Terminal وشغّل:

```bash
cd /Users/yunessaif/Developer/ramash/store
php artisan serve --host=127.0.0.1 --port=8000
```

ثم افتح: http://127.0.0.1:8000

**لم يبقَ خادم يعمل من جلسة البناء:** بيئة التنفيذ منعت فتح المنفذ المحلي (`Operation not permitted`). لم يتم تجاوز هذا القيد. نجحت اختبارات HTTP داخل Laravel دون منفذ شبكة. لم يتسنّ إجراء مراجعة بصرية داخل المتصفح؛ سياسة المتصفح منعت كذلك فتح المعاينة باستخدام `file://`.

## إنشاء حساب المدير

لا يوجد مدير افتراضي أو كلمة مرور مشتركة. أنشئ حسابًا من الطرفية:

```bash
php artisan store:admin
```

سيطلب الاسم والبريد وكلمة مرور لا تقل عن 12 حرفًا؛ كلمة المرور لا تظهر أثناء الكتابة. بعدها سجل الدخول من `/login` وافتح `/admin`.

الحسابات المنشأة من واجهة التسجيل تكون حسابات عملاء، ولا تمنح نفسها صلاحية الإدارة.

## ما تم بناؤه

### واجهة المتجر

- رئيسية ذات صورة حملة أصلية مولدة، وتصنيفات ومختارات وقصة تفصيل وجديد المنتجات.
- واجهة عربية RTL وإنجليزية LTR، وخط عربي مثبت محليًا.
- تصميم متجاوب في CSS للجوال والتابلت وسطح المكتب؛ التحقق المرئي على الأجهزة ما زال مطلوبًا.
- كتالوج من قاعدة البيانات، بحث بالاسم العربي والإنجليزي والوصف.
- تصفية بالتصنيف والسعر والجاهز/التفصيل والعروض، وفرز بالسعر والأحدث.
- صفحات منتج وخيارات مقاس ومخزون وتكبير صورة ووصف وعناية ومنتجات مشابهة.
- اختيار القياسات السابقة أو الجديدة لمنتجات التفصيل.
- مفضلة محفوظة في جلسة المتصفح.
- تقييمات لحسابات مسجلة، تظهر بعد مراجعة المدير. لا توجد تقييمات مصطنعة.
- دليل مقاسات نصي وصفحات شحن واسترجاع وخصوصية وتعريف وتواصل وفروع.

### السلة والطلبات

- إضافة وحذف وتعديل الكمية، مع التحقق من مخزون المقاس.
- حساب الأسعار والإجمالي من قاعدة البيانات على الخادم، لا من مدخلات العميل.
- حد شحن مجاني 375 ريالًا شامل المساواة، ورسوم افتراضية 25 ريالًا دون الحد.
- إتمام كضيف أو حساب مسجل.
- حفظ الطلب وبنوده وعنوانه داخل SQLite.
- خصم ذري للمخزون داخل معاملة قاعدة بيانات، وتراجع كامل عند فشل أي بند.
- رمز إتمام فريد يمنع تكرار الطلب عند إعادة إرسال نفس الطلب.
- طلبات العميل متاحة لحسابه، وطلب الضيف متاح لجلسة إنشائه فقط.
- الطلبات لا تعتبر مدفوعة؛ `payment_status=unpaid`.

### إدارة المتجر

- إضافة منتج جديد بالعربية والإنجليزية ورفع صورة JPG/PNG/WebP حتى 5MB.
- تحديد المقاسات والمخزون والسعر والخامة والتصنيف ونوع الخدمة.
- تعديل الاسم والوصف والسعر والسعر السابق والمخزون والظهور واختيار الرئيسية.
- عرض الطلبات وبيانات العميل والخيارات المطلوبة.
- انتقالات حالة محددة: مراجعة ← تجهيز ← شحن ← مكتمل، وإلغاء قبل الشحن.
- إعادة المخزون مرة واحدة عند الإلغاء.
- نشر التقييمات بعد مراجعتها، وقراءة رسائل التواصل.

لوحة الإدارة عربية. تحرير التصنيفات وصفحات المحتوى والهوية بصريًا، وحذف المنتجات، وتعديل صور المنتجات الموجودة، ليست ضمن لوحة الإدارة الحالية؛ تُدار من المصدر أو البيانات إلى أن تضاف واجهاتها.

## البيانات والأصول

الكتالوج يحتوي **12 منتجًا تجريبيًا و6 تصنيفات**. لا تمثل هذه البيانات منتجات متاحة للبيع أو مواصفات مورد معتمدة. لا توجد فروع أو أرقام تواصل مزيفة.

- `public/images/campaign.png`: صورة حملة مولدة خصيصًا للمشروع؛ ليست من لومار.
- رسوم الثياب SVG: رسوم توضيحية تجريبية، ليست صور منتجات فعلية.
- بقية صور الكتالوج: صور عرض تجريبية من Unsplash، وقد تصور منتجات لعلامات أخرى. تُستبدل بصور المنتجات المملوكة أو المصرح بها قبل البيع.
- الخط Noto Sans Arabic: محلي، مع ملف الترخيص داخل `public/css/OFL.txt` عند توفره.
- الصور محلية. خط Tajawal يُحمّل من Google Fonts، مع Noto Sans Arabic محلي كخط احتياطي عند تعذر الاتصال.

استُخدمت الحزم الموجودة في ذاكرة Composer المحلية بسبب تعذر الاتصال بمستودع الحزم من الطرفية. لا يعتمد المشروع على ملفات أي مشروع آخر، ولا يحتاج Node أو Docker أو عملية بناء JavaScript.

## إعادة التثبيت من المصدر

عند نقل المشروع دون مجلد `vendor` إلى بيئة تسمح بتنزيل الحزم:

```bash
composer install
composer setup
php artisan store:admin
php artisan serve
```

`composer setup` ينشئ `.env` وقاعدة البيانات إن لم تكونا موجودتين، ويولد المفتاح عند غيابه، ويشغل المهاجرات والبيانات التجريبية. البيانات الأولية تستخدم `firstOrCreate` كي لا تستبدل تعديلات المنتجات الموجودة. لا تستخدم `migrate:fresh` على بيانات مهمة.

## إعدادات مهمة

- `.env`: إعدادات البيئة والمفتاح، ولا يُشارك علنًا.
- `config/store.php`: حد الشحن ورسومه ووضع العرض.
- `STORE_DEMO=true`: القيمة الافتراضية؛ تظهر رسائل واضحة بعدم التحصيل أو الشحن.
- `resources/views`: الصفحات ومكونات Blade.
- `public/css/store.css`: الهوية والتجاوب.
- `lang/ar.json` و`lang/en.json`: الترجمات.
- `database/seeders/DatabaseSeeder.php`: بيانات العرض الأولية.

## ما يحتاج ربطًا قبل البيع الفعلي

1. بوابة دفع حقيقية تشمل التحقق من webhook والتوقيع ومنع التكرار والتسوية والاسترداد؛ لا يكفي تغيير `STORE_DEMO`.
2. شركة الشحن وحساب الرسوم والتغطية والتتبع والمرتجعات.
3. بريد إرسال فعلي وإشعارات الطلب واستعادة كلمة المرور والتحقق من البريد؛ هذه غير مفعلة.
4. الكتالوج والصور والأسعار والضرائب والمخزون والسياسات وبيانات الشركة المعتمدة.
5. آلية تشغيل القياسات ومواعيد الفروع؛ الواجهة الحالية تحفظ تفضيل العميل فقط، ولا تؤكد حجزًا أو تسترجع سجل قياسات.
6. اختبارات المتصفح الحقيقية، وإتاحة الاستخدام والأداء وحالات الدفع والشحن قبل النشر.
7. استضافة PHP وتوجيه DocumentRoot إلى `public` فقط، وضبط HTTPS و`APP_DEBUG=false` ونسخ احتياطي وصلاحيات التخزين.

لا توجد حاليًا أكواد خصم أو ولاء أو تعدد عملات أو ربط WhatsApp/CRM أو بوابة دفع حية. لم يُنشر المتجر خارجيًا.

## إدارة ظهور الأقسام

من لوحة التحكم ← **إدارة أقسام المتجر** (`/admin/categories`) يستطيع المدير إظهار أو إخفاء أي قسم. الإخفاء يشمل القوائم والرئيسية والبحث والمفضلة والروابط المباشرة والشراء. تبقى المنتجات والمخزون والطلبات السابقة محفوظة. إعادة الإظهار تعيد المنتجات النشطة فقط، وجميع الأقسام ظاهرة افتراضيًا. إضافة الأقسام وتغيير أسمائها ليست ضمن هذه الإضافة.

تم التحقق بـ21 اختبارًا و182 تحققًا، تشمل الصلاحيات وصحة المدخلات والإخفاء والإظهار والوصول المباشر والسلة.

## نشر الديمو على استضافة

يحتاج الخادم PHP 8.2 أو أحدث مع الإضافات `pdo_sqlite` و`mbstring` و`openssl` و`fileinfo`، وComposer.

```bash
git clone https://github.com/younisoft/ramash.git
cd ramash
composer install --no-dev --optimize-autoloader
cp .env.production.example .env   # مضبوط على https://ramash.sa
composer deploy                    # مفتاح جديد + قاعدة البيانات + بيانات الديمو + الكاش
php artisan store:admin            # إنشاء حساب المدير
```

- وجّه الدومين إلى مجلد `public`. إذا كانت الاستضافة لا تسمح بذلك، فملف `.htaccess` في جذر المشروع يحوّل الطلبات إلى `public` ويمنع الوصول إلى `.env` وبقية الملفات (Apache فقط).
- أعطِ صلاحية الكتابة للمجلدات `storage/` و`bootstrap/cache/` و`database/` و`public/images/`.
- `SESSION_SECURE_COOKIE=true` يتطلب HTTPS. إن كان الموقع يعمل على HTTP فقط فاجعلها `false`، وإلا فلن يعمل تسجيل الدخول والسلة.
- بعد أي تعديل على `.env` شغّل `php artisan config:cache`.
- لإخفاء شارة "قريباً": `STORE_COMING_SOON=false`.
